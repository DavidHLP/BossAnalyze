## 部署注意事项

- `database/migrations/20261108-role-name-unique.sql` 先审计重复角色名，再添加唯一键；检测重复会中止，绝不自动删除或改名。并发唯一性需现库应用该约束后才成立。
- 默认快照已有 `token.create_time`，无需改数据；只有 `created_at` 历史环境才使用可选时间字段对齐脚本。两份迁移均未向现有库执行，真实 MySQL 语法、锁及 DDL 权限仍需部署验证。
- analytics/crawler 必须能访问 `BOSSANALYZE_API_URL`（默认本机 8080）；不可达时返回 503 并拒绝业务执行。API 向 analytics 传播 Bearer 只限配置的 `spark.service.url` 同主机与端口。
- 旧 Redis 缓存记录未批量删除；新登录不再缓存/返回密码。部署前应依据既有缓存到期和隐私流程核对历史值，不在修复过程中清理真实数据。
- 统计接口移除未计算的示例指标；当前前端只读取已计算的访问指标。其他外部调用者需容忍这些未实现字段缺失。

未执行线上部署、现库迁移、真实 Mongo/Minio/Redis/Spark 验收或浏览器验证。远程 CI 与独立代码审查结果将在交付时单独记录。

## 独立需求审查修正

需求轴对 F01–F21 逐项复查，确认两项集成缺陷，已作以下局部修复：

- 下游过滤器与 MVC 对编码路径、matrix 参数的理解不一致：在公开路径/权限匹配前拒绝百分号、分号、反斜线、重复分隔符及非规范点路径；前缀匹配限制为完整路径段。新增 filter + MockMvc 回归，编码前缀、编码 trigger 和 matrix 参数不能到达触发处理器。
- 删除用户的确认密码错误 `1006` 不代表会话失效：HTTP 改为 400，保留 envelope 业务码。实际 UserController + 全局异常处理回归断言不删除用户；前端请求回归确认不清令牌、不发 unauthorized 事件，允许内联纠正重试。真实撤销 token 的 401 行为保留。

修正后重跑完整后端 `clean verify`：43 项通过（commons 9、API 30、analytics 4），无失败/错误/跳过；前端 `pnpm test` 为 51 项通过。需求审查的其余实现映射保留原有数据/部署验证限制，不代表生产验收。
