# Jev 普通路由策略与验收（2026-11-10）

用户明确决定“不需要零数据保留”。该决定取代此前强制 ZDR 的保守门禁，不改变固定 Jev 模型、简历最小化暂停、质量批准、调度/写回或预算规则。

## 行为

- `CMD_ZDR=0`（代码默认值）：不发送 `x-cmd-zdr`，允许正常的已认证职位分析。
- `CMD_ZDR=1`：仍发送 `x-cmd-zdr: 1`；上游 `cmd_zdr_no_providers` 映射为 503，终止请求，不移除 header 或切换模型重试。
- 缺配置、内部认证、输入校验、请求大小、并发、期限、预算保护不变。
- 简历匹配继续在正文消费、简历获取、职位查询及模型调用之前返回 503。取消零保留要求不等于解除该暂停。

普通路由使用远程供应商，按其普通保留政策处理请求；这不是本机离线推理，也不是零数据保留承诺。不得用普通请求成功证明真实模型质量。

## 部署要求

部署新版 Python 时将原服务的 `CMD_ZDR` 从 1 改为 0，并同步当前清单与原重启恢复入口的服务 specification。保留同一 API key、内部 token、固定模型和共享账本，不生成替代凭据或提高额度。Java HTTP 契约未改，不需要因本次策略变化重启其他应用。
