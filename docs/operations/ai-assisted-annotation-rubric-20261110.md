# AI 辅助标注口径（2026-11-10）

本口径用于下一轮离线 AI 辅助预标注、保留分歧与人工复核准备，不是人工 gold、正式质量标准或部署批准。所有此类材料保持 `annotationOrigin=ai_assisted`；本轮语料保持 `dataOrigin=synthetic`，不得伪造 human/reviewed/reviewer。独立人工复核须另留真实身份、版本及仲裁记录。当前没有独立人工 gold/holdout，`qualityApproval`、隐私 hold、ZDR、调度、写回和预算政策不因本文改变。

参考材料为本机 `ai-assisted-review-20261110-ujshdjca` 的 comparison.md、codex-review.md、claude-review.md。第二报告虽然文件名及自述为 Claude，实际执行记录为 DeepSeek；身份以执行记录为准，不能计为指定 Claude 独立评审。两份报告的断言数仅表示各自结构检查，不能折算语义准确率或标注者一致率。

## 阳性与排除项

- 要求：可核验的资格、技能、经验或学历条件。职责（如“维护服务”“电话销售”）单独记录为职责，不由动作名称推导任职资格。
- 否定：保留完整作用域。“不要求销售经验”“学历不限”不是销售/学历正要求；“不提供住宿”不是住宿福利。明确无某经历可作反证，但只限相同技能、领域和时间范围。
- 优先项：辅助材料可纳入 requirements，但必须在外部附录标 preferred 并保留“优先 / Nice to have”等限定语；不能提升成强制项。此为本轮辅助口径，正式 gold 的集合边界须由验收者事前冻结。现有 Evidence schema 没有 modality，外部限定日志不可丢弃，也不能直接塞进 runner JSONL 的额外字段。
- 福利：只收明确正向承诺；“面议”“未提供”“none specified”不产生正福利。“试用期后可申请住宿，具体以制度为准”只记条件机会，保留条件全文，当前不进入 benefits 正例，不改写成确定提供。
- 排除日志：逐项保留 sourcePath、原文跨度、类型、理由、关联 jobId，记录否定、职责、条件、豁免及争议，不因不进入正例而静默丢弃。日志独立于 runner 输入。

## 原文跨度

使用原始未规范化字符串的 Unicode code point，从 0 起，半开 `[start,end)`；`text == source[start:end]`。不能使用 UTF-8 字节或 JavaScript UTF-16 code unit 坐标。🌱 是一个码点，但组合字符与 emoji 序列可能有多个码点，不能按视觉字符数计。

辅助默认取包含限定语的最小自包含资格/福利子句，同一联合条件保留在同一子句；不为提高命中率任意拆分。保留内部空格、标点、emoji，不先 NFKC、去标点或翻译再算跨度。正式比较前双方须冻结粒度规则；不同合理切法仍会影响精确集合指标，原文一致性为 1 只说明切片一致，不证明语义正确。

来源采用 QUALITY-PRIVACY.md 的 canonical 路径，单职位 `/job/jobDescription/...`、多职位 `/jobs/<jobId>/jobDescription/...`，简历单列 `/resume/...`。实际输入形状与全部引用必须同步；旧路径兼容及自动检测边界见该文档。

## 核心项尚未批准

“全部显式强制条件”和“仅关键技术/经验、排除学历”是两份预标注的不同自定规则，均不是已批准核心定义。业务重要性也不等同于强制资格。不得多数票决定学历、年限是否核心，不自行赋权或新增召回门槛。辅助材料保留候选及选择理由并标待仲裁；正式 coreRequirements 在定义与标签未冻结时保持 null，不能用 [] 表示尚未决定。非空核心证据必须为 requirements 子集，优先项不能静默提升成核心。

## 每个 job 的四维 unknown

每个 job 分别记录 skills、relevant_experience、experience、education，对应技能、相关领域经历、经验年限、学历。用 `jobId:dimension` 键对齐，不能用场景/简历级一组布尔代替所有职位。每项另存理由、已知证据及缺失标准，分数未被实际可靠判断时为 null。

- JD 比较标准或简历事实不足时，辅助 unknown=true；一个已知技能不能填满其他技能未知，TypeScript 年限不能挪作 React 年限，泛化参与项目不能自动证明特定领域经验。
- 明确冲突可判断 unknown=false，但这不表示满分，也不直接规定零分；保留反证与限定范围，得分只来自冻结实际输出。
- “No React experience stated”表示未陈述，不能变成“明确没有 React 经历”。未提及不等于否定，证据缺失不能变成零分。
- 明确无门槛和缺少 JD 标准分别记录原因。线上 not_applicable、部分未知不能靠此布尔无损表达；辅助材料单独保存状态，正式映射未冻结前不得把它们强压成可评分或满分。

runner 仍接受合法旧维度键，只核验非空键集合及布尔一致性；本文不声称代码强制四维或验证了理由。

## 排序的可比条件

ranking 属于同一冻结请求；一条 gold 记录可持有多个 job 的完整来源与组级排序，记录 id 与 jobId 是两种身份。groupId 用于隔离同 JD/近重复开发与测试来源，不应为每个 ranking 成员复制同组 gold。排序成员须有非空稳定 jobId，并由复核者对照本次请求确认归属；当前 runner 不提供职位身份注册表。

只有比较对象、简历、维度定义、权重和可评分规则一致且证据足够时才给严格顺序。backend 场景的显式 Kubernetes 反证不能套到 unicode 场景的 React 未陈述上。未冻结权重、证据不足、平局或仅有局部优势时保留 null 及原因，不能强制全排序；现 runner 无平局/部分序表示，正式适配时不可比较映射为 [] 并另存原因。预测排序须来自实际冻结分数，不抄 gold、不为失败或未知职位补零。

空阳性和无 pair 仍报告实际分母及 null/unverifiable，不当满分，不删除稀疏子组美化结果；已测失败继续优先 fail。分类/核心 recall 的数值批准门槛仍待独立验收者决定。成本和延迟须来自完整操作的实际观测，保留失败与重试、未知 null、精确费用及完整总体 p95；AI 辅助标注耗时和模型自述不能充当这些观测。
