# Jev Java deployment and operation

Java owns authorization, bounded candidate selection, database leasing and projection. Python owns Jev inference and its HTTP retry policy. Java sends only the internal `AI_SERVICE_TOKEN`, never a user's JWT, to Python. No credential is required to construct the Java client or start non-AI features. Keep Python private; its health checks must not call a model.

Configure external `AI_SERVICE_URL` (default loopback port 8090), `AI_SERVICE_TOKEN`, and `JEV_MODEL` (default `typesafe/jev-1.14.0`). Both languages must agree on model, `jev-1`, and `jev-policy-1`. The token and provider credentials belong in private deployment configuration. Java never reads CC Switch.

Deployment order:

1. Apply `database/migrations/20261108_job_ai_analysis.sql` twice to a new isolated schema and verify the unique analysis identity and lease contention using separate connections. The script only creates the new InnoDB table; it does not drop, rewrite or certify historical data. Check the existing schema if the table already exists: `IF NOT EXISTS` does not repair schema drift.
2. Deploy C's JSON array readers and sidecar read model before enabling new writes. `source_json` is the original detail_data JSON snapshot (not a selected-field subset); all readers/writers compare only the three factual subtrees through commons JobAnalysisFacts, as defined in the frozen contract. States are in the frozen contract. A result with `status=complete` but row `state=needs_review` is **not** an accepted projection.
3. Explicitly deploy the table before any sidecar reads or AI scheduling. An absent table is a deployment error; this code does not swallow SQL exceptions. Applications never execute DDL at startup.
4. Deploy Java and Python with `crawler.ai.scheduling.enabled=false` and `crawler.ai.writeback-enabled=false`. Verify synthetic contracts, deadline and authorization failures. Resolve annotated-set quality gates before setting writeback true; this boolean is an operator attestation, not a computed quality metric.
5. Enable only an authorized bounded range using `crawler.ai.range-start` (exclusive), `crawler.ai.range-end` (inclusive), then enable scheduling explicitly. Invalid/empty ranges fail before model calls. One synchronous scheduler handles requirements, benefits and core requirements in one inference per job; no second benefits task remains. Each tick keyset-pages the explicit ID range in pages of ten, applying exact-digest eligibility under the source lock; only successful leases count toward the ten-job cap. Terminal states, live leases, future retries and exhausted non-cache identities do not consume that cap. A tick with no eligible jobs may read the entire configured range: keep ranges bounded and validate query/lock cost at deployment. Terminal needs_review/failed rows need an explicit reviewed operator action for retry; no automatic full-database reprocessing exists.

Claim is an atomic conditional UPDATE after an idempotent identity insert. Every claim increments `fence` and leases for 60 seconds. A paid inference claim increments `attempt_count`, with at most three such attempts per identity. A superseded complete/no_evidence cache is revalidated with the same envelope, array and factual-evidence checks before replay, and replay does not spend another inference attempt. No valid cache means the ordinary three-attempt budget applies. Python gets at most 30 seconds per inference; Java performs no HTTP retry. Python may spend its own bounded one-extra-attempt retry budget within that deadline. Expired third attempts without a reusable complete cache become failed on the next current-identity scan; expired cache replays can obtain another fenced lease without spending an inference attempt. Only recoverable 429/502/503/504 failures wait five minutes; deterministic 400/422 terminate immediately as failed with invalid_input_400/invalid_input_422 and NULL next_retry_at. Other rejections terminate as ai_rejected; no scheduled blind retry is allowed. An upstream timeout may already be billed: network exactly-once cannot be promised.

Network calls run outside transactions. Completion opens a short transaction, locks/rechecks the live source and `is_deleted=0`, then conditionally updates the sidecar only for the live fence and unexpired lease. The sidecar and both JSON array projections commit together. A lost fence, expired lease, deletion, changed input, failure or review result never overwrites the previous arrays. New completions supersede other identities for the same job. Preserve this lock order in future writers.

`POST /api/v1/ai/get-user-similarity` retains its successful list and integer similarity shape. It returns 422 for an incomplete candidate range or insufficient evidence instead of silently discarding failures. Empty candidate sets return an empty list. `POST /api/v2/ai/matches` returns `items`, `unrankable`, `consideredCount`, `scope`, `complete`, `model`, and `policyVersion`. Both require live primary-API authentication through DownstreamAuthFilter. Parent integration must add the v2 route to the primary gateway/security and same-origin proxy allowlists if necessary.

Candidates are active, nondeleted jobs, deduplicated across at most ten cities, in ascending ID order, capped at 100; one extra row detects truncation. Scope is explicit; no global ranking is claimed beyond that range. Python batches contain at most ten jobs and share a 30-second request deadline. Rank by original decimal score (ID breaks equal-score ties); v1 alone rounds HALF_UP. Unknown dimensions never become zero. Dependency auth/config/rate errors become 503, deadline exhaustion 504, bad outputs 502; they do not invalidate a user's session.

Requests accept either direct authorized resume text or `resumeId`, not both. `userId` assertions are rejected. Resume IDs are fetched with the user's bearer token from the primary API's ownership-checked `/api/resume/{id}`; only `content` is eligible for inference. Identity-service failure fails closed. Plain-text resumes remove labeled identity/demographic lines, emails and Chinese mobile numbers; unlabelled personal identifiers are not exhaustively detectable. Deployments requiring stronger minimization must use a structured allowlist/redaction step before enabling real resume traffic. No resume, evidence or cross-user match cache is persisted by Java. Input limits: 32K UTF-16 resume units, 256KiB total internal JSON, ten cities, 100 candidates. These are conservative byte/character limits, not token counts. Python owns question/token/day budgets and concurrency gates.

Rollback: disable scheduling and invalidate running leases/fences through an explicitly reviewed operational action, then roll back the application to a JSON-reader-compatible release. Preserve the sidecar and JSON arrays. Never delete volumes, clear tables, reenable old Ollama/OpenRouter execution or replay the whole database for rollback.

Local verification is synthetic and does not prove real MySQL contention, real provider quality/latency/cost, ZDR, resume privacy policy approval, or deployment readiness. Parent acceptance must separately exercise two-connection lease contention, expiration/deletion/source-change races, migration idempotence and atomic rollback in an isolated MySQL schema. No real DDL or model call was executed during implementation.

Integration limit: `AI_MAX_CANDIDATES` (default 192) must be identical for Java and Python. It bounds each full requirements/benefits result; 48 bounds only one classification batch. Core output remains at most 20. Candidate IDs and exact source evidence remain validated.

Fact identity and freshness: only complete `jobDescription`, `jobTags`, `basicInfo` subtrees participate. Missing top-level roots equal null; empty containers/strings and nested structure stay distinct. Recursive key sorting, compact UTF-8 JSON and SHA-256 preserve array order and Unicode. updateTime/analysisReport/company and all other metadata are excluded. Full source_json snapshots remain stored; metadata changes during inference do not invalidate a valid factual result. A real fact change creates a new identity. A→B→A cache replay locks/rechecks the current nondeleted source, updates its full snapshot and lease/fence, then completes through the ordinary fenced transaction outside the claim transaction; no network call occurs for replay. Deploy this first version as one protocol with all commons consumers upgraded; no dual digest compatibility path is supplied for this undeployed version.
