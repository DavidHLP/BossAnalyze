## 实现范围

- 管理端点按现有页面 permission 授权；自身资料、权限和菜单保持认证读取。
- 日志统计要求看板权限，分析触发单独要求 `logs.analysis.trigger`；健康信息脱敏。
- 四个招聘读取路径经认证网关转发，城市条件使用 Spark 类型化字面值比较。
- 已签发会话每次重查角色状态及权限；登录与自助菜单读取同样排除停用权限。
- 角色重名在应用层拒绝；新库唯一约束与现库安全部署说明分开，不自动迁移数据。
- 移除未使用的客户端 Upstash 私有令牌读取及公开构建定义。
- 主动退出确认后才清理会话；强制失效立即清理；临时恢复失败保留 token 并失败闭合。
- 中途 401 保留安全回跳；过期 token 的延迟响应不会清理新会话。
- 隐藏入口与授权可达性分离；菜单图标采用已安装图标白名单；未实现元数据明确标注。
- 跳过导航与页面切换焦点、看板错误分类、统一快照口径和时间、明确占位页状态。
- 薪资区间中点贯通为小数；未知学历/经验保留 null，区别于不限的 0。
- 散点图提供全部聚合分组的折叠分页表，包括抽样未绘制的分组。

## Standards

固定审查范围 `440d8b6...f29e026`。确认 1 项 P2：旧恢复请求的 401 会无条件清理新 token；生产 composable 的隔离延迟 Promise 已复现。补丁让请求层按实际 Authorization 核对当前 token，恢复层重新确认新会话，并删除守卫重复清理。新增延迟 401、503、成功恢复回归，两个实际守卫均覆盖。

另有 1 项 P3 维护性建议：两个守卫的错误分类相似。该项不是硬规范违例；保留现有结构，不为此次修复增加共享路由抽象。

结论：1 个确认问题已修复，1 个维护性建议未采用；最严重确认项为会话竞态。审查不是生产或真实浏览器验收。

## Spec

确认 1 项中等问题：JWT 权限查询排除停用 permission，自助菜单权限查询未排除，导致入口可见而 API 403。`PermissionMapper.listPermissionNamesByRoleId` 已统一增加启用状态条件，覆盖其登录和自助菜单调用者。

采用实际两个 mapper 的 SELECT 注解，在隔离 SQLite 数据库执行 8 条断言：启用、停用、未分配、其他角色、空权限及重新启用。JWT 的 ROLE_ authority 保持不变。此自检不验证 MySQL 驱动、排序规则或线上 schema。

结论：1 个确认问题已修复；最严重确认项为权限读取语义分叉。未新增未要求的业务页面或真实数据操作。

## 边界与部署条件

- 没有修改既有账户、权限、业务记录，没有运行真实分析，没有导入 SQL 快照或迁移现库。
- 现库需先备份、检查重复角色及唯一启用 USER，再显式建立角色名唯一键；应用层检查不能替代并发唯一约束。见 [安全部署说明](../database/migrations/README-role-uniqueness.md)。
- Analytics 自身没有应用认证，其监听端口仍须由可信网络/防火墙隔离；前端网关不能保护另行公开的 analytics 监听器。
- `logs.analysis.trigger` 不自动授予现有角色，需按部署需要显式配置。
- 浏览器快照工具超时，没有截图。未完成完整视觉、窄屏、屏幕阅读器、实体触控、真实数据和生产验收。
- 保留严格数据解析及既有请求超时；没有依据未测耗时风险调大超时或静默丢弃坏数据。
- PR 交付为 ready-for-review，不自动合并或部署；没有把独立代理审查表述为维护者审批。
