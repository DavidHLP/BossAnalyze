# AI 可并行高优先级收尾

## 范围与不变量

实现 2026-11-12 审查中可由 AI 完成的 P1 开发与证据整理，统一在 `feat/ai-closeout-20261112` 集成。关联 #40、#44、#48、#54；本规范不替代这些整体事项的正式验收，不关闭它们。

- 简历匹配保持关闭；Python 与 Java 均应在认证后、消费简历正文前返回现有 503，匿名仍为 401。
- 普通分析保留默认 CMD_ZDR=0；显式 ZDR、固定模型、预算及并发限制不变。
- 不启用质量批准、调度或写回；不调用业务模型、不采集 BOSS、不发送邮件、不执行重启/部署/真实回退，不改业务数据或凭据。
- 人工真值、供应商条款、出站授权政策及正式质量批准不得由 AI 伪造。AI 负责待批准规范及自动化工具。
- 回退检查失败必须显式拒绝；不得覆盖旧 CAS、清空状态或用缺少安全修复的旧版本冒充安全回退基线。

## 任务图

A、B、C、D、E 在本规范冻结后均可开发；先以三路并发推进。F（整合验证和双轴审查）被 A–E 阻塞。每项独立 worktree/分支，完成前合并集成分支最新 tip，随后由独立 merger 汇入集成分支。GitHub 工程子任务仅在 PR 交付后关闭。

### A：Java 正文前匹配拒绝

所有权：crawler AI 控制器/现有鉴权边界、定向测试；不改质量与隐私规范文档。

沿现有认证链把两条公开匹配路由的暂停拒绝放到正文转换前。复用现有错误码、503 响应和路由配置；保持匿名 401 优先，保留 service 层守卫。不要新增可解除暂停的配置。

验收 seam：真实 Spring MVC/过滤器请求边界。认证请求即使正文畸形或正文流不可读取也应返回暂停 503，正文不被读取；匿名 401；普通分析不受影响。先用现有测试入口复现，再最小修复，运行相关模块及凭据契约测试。

### B：只读整体回退预检

所有权：独立的 `tools/rollback-preflight/`（若已有适用入口优先复用）、相关安全文档；不修改私有活动状态、恢复/发布入口或服务。

先阅读本机现有私有 release.py 的 CAS、进程、端口、容器、预算与回退目标契约。建立可版本化、零变更的预检入口，使用显式文件路径与现有身份结构；不复制凭据或私有清单到仓库。若私有格式不适合安全复用，提供最小显式、去敏输入契约及文档化现场适配，而非猜测通过。

验收 seam：CLI 输入/输出与退出码。健康且身份/元数据/预算匹配才报告预检通过；元数据漂移、陈旧 PID/身份、容器变化、pending、未知或不安全回退目标应拒绝，所有情况均无 stop/start/写状态。预检通过不代表执行回退或批准旧版。用隔离合成输入验证拒绝与零变更，不真实触发回退。不自动重建 CAS 基线；文档明确当前旧入口限制与安全重基线前置条件。

### C：冻结输出到离线评估输入

所有权：ai-service 内独立离线转换入口与其定向测试/使用文档；优先复用现有 evaluate 模型，不修改其指标语义。

读取冻结请求与真实响应文件，生成现有 Prediction JSONL。保留候选、连续分数、来源与证据；核对请求职位身份，规范化多职位路径时同步 source/evidence 并转义 jobId。失败/unknown 不补零，缺遥测保持 null。不得读取 gold 生成预测，也不得推断 qualityApproval。

验收 seam：公开转换函数或 CLI 到现有 runner。覆盖多职位、Unicode/转义、重复来源、小数排序、失败/unknown、缺遥测及身份不匹配；明确 synthetic 样例不能作质量证据。先检查是否已有完整实现，有则复用而非新增重复工具。

### D：待批准的人工评估与隐私授权规范

所有权：新规范文档和必要的 QUALITY-PRIVACY/hold 文档链接；不改生产代码。

完成可审阅的标注协议：要求/职责/优先项、核心项、跨度粒度、unknown/not_applicable、平局/不可比较、子组、按 JD 来源分组的开发/留出划分、仲裁与排除记录。补齐简历字段白名单与转换、用途/供应商/保留/撤回/授权记录、入口到门禁和对抗测试矩阵、回滚条件。样本量和准入阈值保留明确待批准状态，不把示例设成正式门槛。

验收：与现有 schema/runner 兼容，提供空白模板或字段说明而非伪 reviewed/human 记录；人类与供应商决定逐项列出。规范完成仅关闭编写子任务，不能据此重开匹配或批准质量。

### E：恢复证据核对

所有权：新的去敏运行证据报告及 reboot-recovery 文档的当前核验补充；不改 B 的文件和私有恢复脚本。

核对 journal、boot、linger、五组件运行身份与监听归属、现行恢复 specification 及现有验收脚本的适用性。只读核验，无法可靠确认的项目标 unverifiable；不能把 linger=yes 或历史 accepted 单独视为无人登录恢复验收。能安全重跑的现有只读断言才重跑，涉及数据写入/凭据输出/模型调用则跳过并解释。

验收：每个结论有时间、修订、来源和限制，不公开私有环境/凭据/完整清单；不由时间戳矛盾推导成功，不把历史测试数累加成当前成绩。不改变服务状态。

## 集成验收

复用既有测试，以本次风险为 seam 进行 TDD：A HTTP 拒绝边界、B CLI 拒绝与零变更、C 转换到评估输入。上述 seams 来自本任务验收范围；用户已要求纯 AI 开发，不再等待逐个测试接口确认。文档任务进行规范与证据审阅，不编造单元测试。

集成后执行受影响 Python、Java/凭据检查及完整项目要求的构建门禁，开展固定基线的 Standards/Spec 独立审查。修复发现后创建/更新同一 PR；CI/平台门禁通过后按仓库工作流交付。未执行真实模型/人工质量/账号采集/重启回退应始终明确保留。
